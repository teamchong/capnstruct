## Why Use `capnstruct`?

When you pass thousands of structured records over `fetch`, a WebSocket, `postMessage` to a Web Worker, or into WebAssembly:

1. **`JSON.parse` / `JSON.stringify` is easy to write, but expensive at scale:** Parsing 100,000 rows allocates 100,000 separate JS objects on the heap and eagerly decodes every UTF-8 string—even if your loop only checks two numbers. Updating a single field requires re-serializing the entire payload.
2. **A `Uint8Array` has zero parse cost, but is painful to use by hand:** Transferring or reading a binary buffer is fast, but nobody wants to maintain manual `DataView` offset arithmetic (`dv.getFloat64(base + i * 24 + 8, true)`) or give up normal property assignment (`row.callsign = 'NEW'`) and `.push()` / `.pop()`.

`capnstruct` lets you define a typed schema once and work with a `Uint8Array` or `WebAssembly.Memory` buffer using ordinary JavaScript syntax:

```ts
import { defineStruct, u32, f64, str, slice } from 'capnstruct';

const Telemetry = defineStruct('Telemetry', {
  id: u32,
  lat: f64,
  lon: f64,
  callsign: str,
  tags: slice(u32),
});

// 1. Growable binary array — push & pop like a normal JS array
const rows = Telemetry.alloc(0);
rows.push(
  { id: 1, lat: 37.6188, lon: -122.375, callsign: 'SFO_101', tags: [10, 20] },
  { id: 2, lat: 51.47, lon: -0.4543, callsign: 'LHR_202', tags: [30] },
);

// 2. Zero-allocation flyweight iteration + lazy UTF-8 decoding
for (const row of rows) {
  if (row.lat > 40) {
    // 3. In-place mutation of primitives, strings, and slices
    row.callsign = 'LHR_PRIORITY';
  }
}

// 4. Columnar TypedArray projection for Apache Arrow / WebGPU / SIMD
const lats: Float64Array = rows.column('lat');

// 5. Underlying Uint8Array ready for fetch, WebSocket, Worker, or WASM
const wireBytes: Uint8Array = rows.bytes;
```
