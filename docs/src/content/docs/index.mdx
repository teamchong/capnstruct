**Why Data Layout Beats Switching JS Engines:** Switching from Node.js (V8) to Bun (JavaScriptCore) speeds up `JSON.parse` + `.filter()` or `structuredClone` by **1.3x–2.7x**, because both engines still have to allocate tens of thousands of boxed heap objects (**+6 MB to +14 MB JS heap** per call), chase out-of-line pointers across CPU cache lines, and pause for garbage collection. Changing your data layout to `capnstruct` on standard Node.js yields **6.5x to 3,520x speedups** with **0.00 MB of JS heap allocation**—and natively handles circular object graphs (`a.next = b; b.next = a`) where `JSON.stringify` crashes with `TypeError`.

## What You Can Build With `capnstruct`

### 1. Single Binary Structs, Protocol Headers & Nested Messages (`0` Offset Math)
`capnstruct` is not just for arrays. Wrap any single packet, file header, or nested RPC message in a `StructView` via `Schema.view(bytes)` or allocate one via `Schema.create({...})`:

```ts
import { defineStruct, u8, u16, u32, i16, i32, f16, fixedStr, fixedBytes, sentinel, scaled, str, slice } from 'capnstruct';

const Waypoint = defineStruct('Waypoint', {
  lat: scaled(i32, 1e6),          // stores compact 4B i32 on wire, reads/writes float degrees in JS
  lon: scaled(i32, 1e6),
  alt: sentinel(i16, -32768),     // -32768 sentinel on wire <-> null in JS (0 extra validity bytes)
});

const RadarPacket = defineStruct('RadarPacket', {
  magic: fixedStr(4),             // inline [u8; 4] ASCII ("RADR") — 0 tail pointer overhead
  icao: fixedStr(6),              // inline [u8; 6] hex ID
  hmac: fixedBytes(16),           // inline [u8; 16] zero-copy Uint8Array sub-slice
  seq: u32,
  snr: f16,                       // 2-byte IEEE 754 half-precision float
  callsign: str,                  // variable-length UTF-8 string in tail arena ([u32 off, u32 len])
  route: slice(Waypoint),         // variable-length nested struct slice in tail arena
});

// Allocate and initialize a single binary struct (or wrap an incoming packet via RadarPacket.view(uint8))
const pkt = RadarPacket.create({
  magic: 'RADR',
  icao: 'a8b2c3',
  seq: 42,
  snr: 18.5,
  callsign: 'SFO_101',
  route: [
    { lat: 37.6188, lon: -122.375, alt: null },
    { lat: 35.6762, lon: 139.6503, alt: 35000 },
  ],
});

// Direct property reads & in-place mutation on the underlying binary buffer
pkt.seq += 1;
pkt.callsign = 'SFO_101_EXPRESS';
console.log(pkt.magic, pkt.route.at(0).alt, pkt.route.at(1).lat); // "RADR", null, 35.6762

// Wire-ready Uint8Array (automatically compacts dead tail bytes if mutated)
const wireBytes: Uint8Array = pkt.bytes;
```

### 2. Zero-Copy JS &harr; Rust / C / Zig WebAssembly (`WasmArena`)

Passing structs between JavaScript and WebAssembly via `serde-wasm-bindgen` or JSON serializes every field across the FFI boundary. Writing manual `Uint32Array` / `Float64Array` index arithmetic (`outU32[ptr + i * 16 + 8]`) breaks whenever a struct field changes or `memory.grow()` detaches the buffer.

With `capnstruct`, TypeScript and Rust/C/Zig read and write the **exact same `#[repr(C)]` bytes** inside `WebAssembly.Memory`:

```ts
// Before: Brittle manual pointer arithmetic that breaks when WebAssembly.Memory grows
const outBuf = wasm.memory.buffer;
const hdrU32 = new Uint32Array(outBuf, hdrPtr, 17);
const hitsF64 = new Float64Array(outBuf, hdrU32[15], hdrU32[7] * 8);
const lat = hitsF64[i * 8], lon = hitsF64[i * 8 + 1];
```

```ts
// After: Declarative #[repr(C)] view with automatic WebAssembly.Memory.grow() re-binding
import { WasmArena, defineStruct, u32, f64, fixedArray } from 'capnstruct';

export const IOHeader = defineStruct('IOHeader', {
  num_samples: u32,
  out_hits_ptr: u32,
  out_hits_count: u32,
});

export const OutHit = defineStruct('OutHit', {
  lat: f64,
  lon: f64,
  start: f64,
  pre: f64,
  set_idx: u32,
  n_flights: u32,
  fids: fixedArray(u32, 6),
});

const arena = new WasmArena(wasm.memory, 64);
const hdr = arena.allocOne(IOHeader);

wasm.run_search(hdr.byteOffset); // Even if WASM calls memory.grow() inside run_search(),
                                 // hdr re-binds automatically on the next property read!

for (const hit of OutHit.array(wasm.memory, hdr.out_hits_ptr, hdr.out_hits_count)) {
  console.log(hit.lat, hit.lon, hit.fids[0]); // 0 JS object allocations per row
}
```
Generate matching **Rust `#[repr(C)]` structs** (`CapnStr`, `CapnSlice<T>`, `CapnRef<T>`) with compile-time `size_of` / `align_of` / `offset_of!` assertions from the exact same schema:

```bash
npx capnstruct ./src/schema.ts -o ./src/schema_generated.rs
npx capnstruct ./src/schema.ts -o ./src/schema_generated.go --pkg radar
```

### 3. Web Worker `SharedArrayBuffer` & `postMessage` (`~1,150x` Faster Than `structuredClone`)

Sending an array or state tree of 25,000 objects to a Web Worker via `postMessage(data)` runs `structuredClone`, freezing the main thread for ~45 ms while deep-cloning every object and string across heaps.

With `capnstruct`, keep your state in a `SharedArrayBuffer` (or transferable `ArrayBuffer`) and mutate fields in place from either thread with `0 ms` serialization cost:

```ts
// main.ts — share the backing buffer once (0 ms clone overhead)
const sab = new SharedArrayBuffer(2 * 1024 * 1024);
const rows = Telemetry.array(sab, { byteOffset: 0, count: 25_000 });
worker.postMessage({ buffer: sab, count: rows.length });

// worker.ts — mutate primitives, strings, and slices in place
const view = Telemetry.array(buffer, { byteOffset: 0, count });
const cur = view.cursor();
for (let i = 0; i < view.length; i += 250) {
  cur.seek(i).callsign = 'UPD_999'; // Overwrites UTF-8 bytes in place (0 allocations)
}
```

### 4. Zero-Heap Queryable Tables, Columnar Projections & Schema Evolution

Unpacking binary payloads into `[{ ts, lat, lon, ... }]` JS arrays just to binary-search a time window or filter rows causes 8x V8 heap amplification and major GC pauses. `StructArrayView` queries and slices binary buffers directly in external memory:

```ts
// 1. O(log N) binary search time-window slice (~0.0027 ms on 100k rows, 0 allocations)
const windowView = samples.rangeBy('t', 1700000000, 1700000600);

// 2. Zero-heap binary filtering -> returns a packed Uint8Array ready for network/Worker transfer
const matchedBytes = windowView.filterBytes((row) => row.val > 50.0);

// 3. Bulk memcpy chunk concatenation
const mergedBytes = SpdSample.concatBytes([chunkA, chunkB, matchedBytes]);

// 4. Zero-copy TypedArray column extraction for WebGPU, WebGL, DuckDB, or Apache Arrow
const vals: Float64Array = samples.column('val');
```

### 5. Circular References & Recursive Schemas (`ref(() => Node)`)

`JSON.stringify` throws `TypeError: Converting circular structure to JSON` on circular references, and V8's `structuredClone` overflows the C++ call stack on deep linked structures. `ref(() => Struct)` stores an 8-byte relative-offset pointer (`[u32 relOffset, u32 present]`) that packs cyclic JS graphs into a flat `Uint8Array` in $O(1)$ stack space, traverses cycles in $O(1)$ with zero allocations, and reconstructs circular JS references via `.toObject()`:

```ts
import { defineStruct, u32, str, ref, slice } from 'capnstruct';

const GraphNode: any = defineStruct('GraphNode', {
  id: u32,
  label: str,
  next: ref(() => GraphNode),
  children: slice(() => GraphNode),
});

const n1: any = { id: 1, label: 'alpha', next: null, children: [] };
const n2: any = { id: 2, label: 'beta', next: n1, children: [] };
n1.next = n2; // cycle: n1 <-> n2
n1.children = [n2];

const bytes = GraphNode.pack([n1, n2]);
const view = GraphNode.array(bytes);

// Zero-allocation O(1) cyclic traversal across arbitrary depth
console.log(view.at(0).next.next.id); // 1

// Cycle-preserving materialization back to circular JS objects
const obj = view.at(0).toObject();
console.log(obj.next.next === obj); // true
```

## Wire Layout & Safety Guarantees

```text
+------------------------------------------------------------------+
| Fixed #[repr(C)] Struct Table (N * def.size bytes, 8B-aligned)    |
+------------------------------------------------------------------+
| Row 0: [primitive | fixedStr | CapnStr(off,len) | CapnRef(off)]  |
| Row 1: [primitive | fixedStr | CapnStr(off,len) | CapnRef(off)]  |
+------------------------------------------------------------------+
| Optional Tail Arena (UTF-8 strings, slices & ref targets)        |
|   offset = structBaseOffset + relOff                             |
+------------------------------------------------------------------+
```

1. **Zero-Header Fixed Layouts**: Structs using only primitives, `fixedArray`, `fixedStr(N)`, `fixedBytes(N)`, `sentinel()`, `scaled()`, and `f16` have **zero pointers and zero tail arena**—the buffer is 100% byte-for-byte identical to a C/Rust `#[repr(C)]` struct or array.
2. **Wire-Safe Pointer Bounds & Amplification Defense**: Wrapping a `Uint8Array` sub-slice clamps the `DataView` window to `[byteOffset .. byteOffset + byteLength]`. Every relative `[u32 off, u32 len]` tail descriptor is validated against `[structEnd .. bufferEnd]` (`RangeError('Out of bounds')` on corrupt/negative/overflowing offsets), and `.toObject()` / `.toObjects()` enforce an `8x` traversal budget against pointer-aliasing amplification attacks while preserving valid object cycles.
3. **Cap'n-Style Wire Stride Evolution**: Pass an older schema to `NewSchema.array(v1Bytes, OldSchema)` to read older binary payloads with zero copying; fields beyond the older wire stride return default values (`0`, `""`, `[]`, `null`) and automatically upgrade in place on mutation.
