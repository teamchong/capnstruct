## Why JavaScript Needed a New Data Standard

For years, JavaScript and TypeScript developers had to choose between two painful extremes:

1. **Plain JS Objects & `JSON.parse` / `JSON.stringify`**: Ergonomic (`row.lat`, `row.callsign = 'NEW'`, `rows.push(...)`, `{ ...row }`), but parses every byte upfront, allocates millions of short-lived V8 heap objects, triggers GC pauses, and requires full re-serialization to cross Worker or WASM boundaries.
2. **Manual `DataView` / `apache-arrow` / Protobuf**: Zero-copy or binary-compact, but breaks normal JS ergonomics (`dv.getFloat64(base + i * 24 + 8, true)` or `table.getChild('lat').get(i)`), produces **immutable** buffers where you cannot assign `row.name = 'new'` or `rows.push(...)`, and ships 100–150+ KiB of runtime code.

**`capnstruct` gives you both at once** in a **0-dependency, &lt; 4.5 KiB** runtime:

```ts
import { defineStruct, u32, f64, str, slice } from 'capnstruct';

const Telemetry = defineStruct('Telemetry', {
  id: u32,
  lat: f64,
  lon: f64,
  callsign: str,
  tags: slice(u32),
});

// 1. Growable binary array — push & pop like a normal JS array
const rows = Telemetry.alloc(0);
rows.push(
  { id: 1, lat: 37.6188, lon: -122.375, callsign: 'SFO_101', tags: [10, 20] },
  { id: 2, lat: 51.47, lon: -0.4543, callsign: 'LHR_202', tags: [30] },
);

// 2. Zero-allocation flyweight iteration + lazy UTF-8 decoding
for (const row of rows) {
  if (row.lat > 40) {
    // 3. Live in-place mutation of primitives, strings, and slices!
    row.callsign = 'LHR_PRIORITY';
  }
}

// 4. Columnar TypedArray projection for Apache Arrow / WebGPU / SIMD
const lats: Float64Array = rows.column('lat');

// 5. Wire-ready Uint8Array (automatically compacts dead tail bytes if needed)
const wireBytes: Uint8Array = rows.bytes;
```
