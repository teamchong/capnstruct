## 1. `WasmArena` & `WebAssembly.Memory.grow()` Auto-Rebinding

When sharing memory with a WebAssembly module (`WebAssembly.Memory`), calling `memory.grow()` or allocating inside a growable arena **detaches** the old `ArrayBuffer`, invalidating standard JavaScript `DataView` and `TypedArray` instances.

`WasmArena` bump-allocates aligned structs, arrays, and variable-length tail strings/slices directly inside `WebAssembly.Memory` (or a growable `ArrayBuffer`). Every `StructView` and `StructArrayView` created from the arena tracks the arena and **automatically re-binds** to the new `ArrayBuffer` whenever `memory.grow()` is called:

```ts
import { WasmArena, defineStruct, u32, f32, str } from 'capnstruct';

const QpPoint = defineStruct('QpPoint', {
  x: f32,
  y: f32,
  origIdx: u32,
  label: str,
});

// Create a 1-page (64 KiB) WebAssembly.Memory and wrap it in WasmArena (starting at offset 64)
const wasmMemory = new WebAssembly.Memory({ initial: 1 });
const arena = new WasmArena(wasmMemory, 64);

// Allocate a 1,000-element StructArrayView inside WASM linear memory
const points = arena.alloc(QpPoint, 1000);
points.at(0).set({ x: 1.5, y: -2.5, origIdx: 7, label: 'radar-0' });

// Even if WASM or JS grows WebAssembly.Memory (detaching the old ArrayBuffer),
// existing StructView and StructArrayView instances re-bind on access:
wasmMemory.grow(4);
console.log(points.at(0).x, points.at(0).label); // 1.5, 'radar-0'

// Pass byteOffset and length directly to your exported WASM kernel:
// wasmExports.process_points(points.byteOffset, points.length);
```

## 2. Rust `#[repr(C)]` Codegen (`capnstruct/codegen` & CLI)

`capnstruct/codegen` and the `capnstruct` CLI generate exact **Rust `#[repr(C)]` struct definitions** (`toRustReprC`), including zero-copy `CapnStr`, `CapnSlice<T>`, and `CapnRef<T>` helpers and compile-time `size_of` / `align_of` / `offset_of!` assertions directly from your TypeScript schemas. Recursive and mutually recursive schemas (`ref(() => Node)`, `slice(() => Node)`) are handled automatically without duplicate definitions.

### Programmatic API

```ts
import { toRustReprC } from 'capnstruct/codegen';
import { SpdSample } from './schema.js';

console.log(toRustReprC([SpdSample]));
```

### CLI Usage

```bash
npx capnstruct ./src/schema.ts -o ./src/schema_generated.rs
```

### Generated Rust Output

```rust
// Auto-generated by capnstruct. DO NOT EDIT.
#![allow(dead_code, non_camel_case_types, non_snake_case)]

#[repr(C)]
#[derive(Copy, Clone, Debug, PartialEq, Eq)]
pub struct CapnStr {
    pub off: u32,
    pub len: u32,
}

#[repr(C)]
#[derive(Copy, Clone, Debug, PartialEq, Eq)]
pub struct CapnSlice<T> {
    pub off: u32,
    pub len: u32,
    pub _marker: core::marker::PhantomData<T>,
}

#[repr(C)]
#[derive(Copy, Clone, Debug)]
pub struct SpdSample {
    pub t: u32,
    pub _pad0: [u8; 4],
    pub val: f64,
    pub id: u32,
    pub _pad1: [u8; 4],
}

const _: () = {
    assert!(core::mem::size_of::<SpdSample>() == 24);
    assert!(core::mem::align_of::<SpdSample>() == 8);
    assert!(core::mem::offset_of!(SpdSample, t) == 0);
    assert!(core::mem::offset_of!(SpdSample, val) == 8);
    assert!(core::mem::offset_of!(SpdSample, id) == 16);
};
```

## 3. Go & TinyGo Zero-Copy Struct & WebAssembly Codegen (`toGoStruct` & CLI)

`toGoStruct` (alias `generateGo`) and `npx capnstruct` generate zero-copy Go struct definitions that work identically across **64-bit native Go** (`amd64`/`arm64`), **standard Go WebAssembly** (`GOOS=wasip1 GOARCH=wasm` / `GOOS=js GOARCH=wasm`), and **TinyGo WebAssembly** (`tinygo build -target=wasi -opt=2 -no-debug`, producing compact ~26 KiB WASM binaries):

- **32-Bit WASM vs. 64-Bit Native Layout Parity**: On 32-bit WebAssembly targets (especially TinyGo `wasm32`), natural alignment of `uint64`/`int64`/`float64` is 4 bytes instead of 8 bytes. `toGoStruct` inserts explicit `_padN [k]byte` fields before every 8-byte field and at the struct tail so the memory layout is 100% byte-for-byte identical across JS `DataView`, Rust `#[repr(C)]`, Go `wasip1/wasm`, TinyGo `wasi`, and 64-bit native Go—verified at compile time by `unsafe.Sizeof` and `unsafe.Offsetof` blank-constant assertions.
- **Zero-Copy Linear Memory Views (`CapnBytes`, `CapnView[T]`, `CapnSliceView[T]`)**: Cast any `(ptr uintptr, byteLen uint32)` passed across a `//go:wasmexport` boundary directly into a `[]T` or `*T` slice in $O(1)$ without copying or decoding.
- **Pinned WASM Arena Exports (`{ wasm: true }` / `--go-wasm`)**: Emits `//go:wasmexport capn_alloc` (8-byte aligned bump allocation pinned against Go/TinyGo GC collection) and `//go:wasmexport capn_reset` so the JS host can write packed `capnstruct` bytes directly into `wasmInstance.exports.memory.buffer`.

### Programmatic API & CLI

```ts
import { toGoStruct } from 'capnstruct/codegen';
import { SpdSample, RingNode } from './schema.js';

// Native Go package (default pkg: 'capnschema')
console.log(toGoStruct([SpdSample, RingNode], { pkg: 'radar' }));

// Go / TinyGo WASM module (default pkg: 'main', emits //go:wasmexport capn_alloc & capn_reset)
console.log(toGoStruct([SpdSample, RingNode], { wasm: true }));
```

```bash
# Native Go package
npx capnstruct ./src/schema.ts -o ./src/schema_generated.go --pkg radar

# Go WASM (GOOS=wasip1 GOARCH=wasm) or TinyGo WASM (-target=wasi)
npx capnstruct ./src/schema.ts -o ./src/main_schema.go --go-wasm
```

### Generated Go / TinyGo WASM Output (`--go-wasm`)

```go
// Auto-generated by capnstruct. DO NOT EDIT.
package main

import "unsafe"

var _capnPin [][]byte

//go:wasmexport capn_alloc
func CapnAlloc(n uint32) uintptr {
	if n == 0 {
		return 0
	}
	b := make([]byte, int(n)+8)
	_capnPin = append(_capnPin, b)
	return (uintptr(unsafe.Pointer(&b[0])) + 7) & ^uintptr(7)
}

//go:wasmexport capn_reset
func CapnReset() {
	_capnPin = _capnPin[:0]
}

func CapnBytes(ptr uintptr, byteLen uint32) []byte {
	if ptr == 0 || byteLen == 0 {
		return nil
	}
	return unsafe.Slice((*byte)(unsafe.Pointer(ptr)), int(byteLen))
}

func CapnView[T any](b []byte) *T {
	var zero T
	if uint64(len(b)) < uint64(unsafe.Sizeof(zero)) {
		panic("CapnView out of bounds")
	}
	return (*T)(unsafe.Pointer(unsafe.SliceData(b)))
}

func CapnSliceView[T any](b []byte, n uint32) []T {
	if n == 0 {
		return nil
	}
	var zero T
	if uint64(n)*uint64(unsafe.Sizeof(zero)) > uint64(len(b)) {
		panic("CapnSliceView out of bounds")
	}
	return unsafe.Slice((*T)(unsafe.Pointer(unsafe.SliceData(b))), int(n))
}

type SpdSample struct {
	T uint32
	_pad0 [4]byte
	Val float64
	Id uint32
	_pad1 [4]byte
}

const (
	_ = uint(unsafe.Sizeof(SpdSample{})-24) + uint(24-unsafe.Sizeof(SpdSample{}))
	_ = uint(unsafe.Offsetof(SpdSample{}.T)-0) + uint(0-unsafe.Offsetof(SpdSample{}.T))
	_ = uint(unsafe.Offsetof(SpdSample{}.Val)-8) + uint(8-unsafe.Offsetof(SpdSample{}.Val))
	_ = uint(unsafe.Offsetof(SpdSample{}.Id)-16) + uint(16-unsafe.Offsetof(SpdSample{}.Id))
)
```

### Building & Calling Go / TinyGo WASM Kernels from JS

Write a `//go:wasmexport` kernel alongside your generated `main_schema.go`:

```go
// kernel.go
package main

//go:wasmexport scan_samples
func scan_samples(ptr uintptr, byteLen uint32, count uint32) float64 {
	rows := CapnSliceView[SpdSample](CapnBytes(ptr, byteLen), count)
	var sum float64
	for i := range rows {
		sum += rows[i].Val
	}
	return sum
}

func main() {}
```

Compile with either **standard Go** (`1.24+`) or **TinyGo** (`0.34+`):

```bash
# Option A: Standard Go WASM
GOOS=wasip1 GOARCH=wasm go build -buildmode=c-shared -o kernel.wasm .

# Option B: TinyGo WASM (~26 KiB binary, 0.084 ms for 100k rows)
tinygo build -buildmode=c-shared -target=wasi -opt=2 -no-debug -o kernel.wasm .
```

Pass packed `capnstruct` bytes from JavaScript into Go/TinyGo WASM linear memory with zero serialization:

```ts
const bytes = SpdSample.pack(samples);
const ptr = wasmExports.capn_alloc(bytes.byteLength);
new Uint8Array(wasmExports.memory.buffer, ptr, bytes.byteLength).set(bytes);

// Executes in ~0.084 ms (TinyGo) / ~0.107 ms (Go WASM) for 100,000 rows!
const total = wasmExports.scan_samples(ptr, bytes.byteLength, samples.length);
wasmExports.capn_reset();
```
